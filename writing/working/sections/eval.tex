\subsection{Experiment Design}
\label{sec:exp-design}

To answer the four research questions we run four families of experiments on the same dataset (\autoref{sec:dataset}).

\subsubsection{Experiments for RQ1 -- Comparison to Existing Approaches}
\label{sec:exp:rq1}

We run two evaluations on the same five projects (\autoref{sec:dataset}):
\begin{enumerate}[leftmargin=*]
    \item \emph{Doc-to-model.} For every sentence in the architecture document, we use \approach to link it back to architectural components.
     We then compare recovered links with the doc-to-model gold standard links. 
    We compare \approach{} with \emph{SWATTR}~\cite{keim_trace_2021}, the lexical NLP pipeline by string similarity and with \emph{Artemis}~\cite{fuchs_whos_2025}, a recent \ac{LLM}-based link recovery tool. 
    This is the link task where \approach{} can directly show its strength. 
    %todo, add lisa to both task, like swattr, lissa, artemis, 
    \item \emph{Doc-to-code.} For every sentence we recover the code files it talks about and compare them with the link-level gold standard. 
    \approach{} reaches code files using a transitive linking approach, the same composition used by TransArc.
    It combinines its doc-to-model links with the architecture model's component-to-file mapping via ArCotl\cite{keim_recovering_2024}. 
    We compare \approach{} with \emph{TransArc}~\cite{keim_recovering_2024}, the strongest heuristic based approach, 
    and with \emph{Artemis} as an \ac{LLM} baseline. %todo, add lisa to both task, like transarc, lissa, transarc-artemis, 
\end{enumerate}
For each task we use the same metrics \emph{TransArc} and \emph{Artemis} use. 
We report link level precision, recall, and \fone per project and averaged across projects (both macro and micro).
The outcome of \ref{RQ1 SOTA comparison} tells us whether \approach{} improves over existing tools on the link task it targets directly (doc-to-model) and on the downstream task that developers care about (doc-to-code).


\subsubsection{Experiments for \ref{RQ2 metrics} -- Architecture-Driven Metrics}
\label{sec:exp:rq2}

The metric suite from \autoref{sec:metric:suite} is motivated in the pre-study in \autoref{sec:metric:prestudy},
where two naive baselines (a Top-3 baseline per task and a random baseline) confirm that per-component \fone, sentence coverage, and noise rate each carry information the standard link-level \fone\ does not.
Here we apply the validated suite to \approach{} and the doc-to-code baselines (TransArc, LiSSA) from \ref{RQ1 SOTA comparison}, and to \approach{} and the doc-to-model baselines (SWATTR, LiSSA).
%add artemis, file-level to link level  

For each (system, project, task) cell we recompute the four primary metrics: file-level \fone, per-component \fone, sentence coverage, and noise rate. We report per-project values plus macro means. Per system we provide two diagnostic views:
\begin{enumerate}[leftmargin=*]
    \item a \emph{per-component \fone\ distribution}, showing which components are fully covered, which are uncovered, and where false-positive and false-negative mass concentrates;
    \item a \emph{per-sentence coverage--noise scatter}, splitting gold sentences into served-cleanly, served-noisily, and unserved, with the share of each reported per system.
\end{enumerate}
Across systems and projects we report the rank correlation between file-level \fone\ and each other primary metric.

\subsubsection{Experiments for RQ3 -- Validator Contribution}
\label{sec:exp:rq3}
We build three ablations of \approach{} that remove validators while keeping the linker agents in place. 
We compare each ablation against \emph{\fullVariant{}}, the full pipeline.

%TODO, also define macro for validators
\begin{enumerate}[leftmargin=*]
\item \emph{\noEntityValid{}}: skip the entity validator (Phase 4 in \autoref{sec:approach}); accept all candidates from the entity extractor without the p1 \ensuremath{\wedge} p2 evidence gate.

\item \emph{\noCitation{}}: skip the coreference validator; accept all coreference candidates without the quoted-antecedent gate.

\item \emph{\noValidator{}}: skip both validators (the two above combined).
\end{enumerate}

Consensus voting in the entity extractor (the two-pass intersection at \autoref{sec:approach}) is kept inside \fullVariant{} as part of the extractor and is not ablated separately; reconstructing a no-consensus counterfactual would require new LLM calls and is out of scope.

\subsubsection{Experiments for RQ4 -- Per-Agent Ablation}
\label{sec:exp:rq4}

%TODO, also disable knowledge layer-> no alias / ambiguous component + run full linker , 
We measure each linker by leave-one-out ablation across the two linkers: \linkerB{} and \linkerC{}.
The knowledge layer (\autoref{sec:approach}) stays in place in every run, because both linkers read from it.
For each variant we report:
\begin{enumerate*}[label=(\roman*)] \item the change in macro \fone over the
five projects, \item the change in sentence coverage and noise rate, which tells
us whether the removed agent added recall or only filtered false positives, and
\item how many true positives are lost that no other agent recovers.
\end{enumerate*} Set overlap is reported via the UpSet decomposition \texttt{|only\_E|}, \texttt{|both|}, \texttt{|only\_C|} in \autoref{fig:rq4-upset}; per-linker unique-TP counts in \autoref{tab:rq4-agents}.


\subsection{Dataset}
\label{sec:dataset}

%%%%TODO, also show how bias and long tail distribution in trace links
We use the ardoco benchmark, the largest architectural traceability benchmark to the best of our knowledge~\cite{fuchs_establishing_2023}.
It contains five Java open-source systems with hand-curated architecture docs, an architecture model, and a gold standard at two grains, sentence-to-component and sentence-to-file:
\emph{MediaStore}, \emph{TeaStore}, \emph{Teammates}, \emph{BigBlueButton}, and \emph{JabRef}.
We use this benchmark because it is the standard evaluation set for this task~\cite{keim_recovering_2024,fuchs_lissa_2025}.

\input{table/dataset-stat}

The dataset statistics list, per project, the number of sentences in the architecture document, the number of components in the architecture model, the number of code files, the number of human gold decisions, and the number of link-level pairs after each directory decision is expanded to its files.
The expansion factor differs by two orders of magnitude across projects (1.0$\times$ for MediaStore, 217.6$\times$ for JabRef).
This is one of the reasons we report the extra metrics in \ref{RQ2 metrics}.

For each project we use the architecture document as input~$D$, the architecture model as the component set~$C$, and the gold standard as the ground-truth links between sentences of~$D$ and components of~$C$ (or files belonging to components of~$C$, for the doc-to-code task).
We use the official benchmark loaders for $D$ and $C$ to stay aligned with prior work.
