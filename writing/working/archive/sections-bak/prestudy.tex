\subsection{Prestudy: Understanding Architectural Decay}
\label{prestudy:prestudy}


% Architectural smells evolve as projects mature, and components become increasingly smelly over time \cite{decay_icsa18,woods_ContinuousArchitecture_2021,ford_SoftwareArchitecture_2021,fontana_2017,taibi_DefinitionMicroservice_2018}.
While existing approaches such as \RecovAr~\cite{shahbazian_recovering_2018} and ADDRA~\cite{jansen_documenting_2008} can recover \aclp{ADD} from architectural change-related issues (\ac{ADD} issues), they are not well-suited to studying smell evolution specifically.

We identify two key limitations:
First, \ac{ADD} issues might not cover all \ac{ASI} issues.
\textbf{Commonality:} \ac{ADD} issues are captured by detecting architectural changes at the component-entity level, such as files moving between components.
Architectural smells primarily concern inter-component dependencies \cite{as_catalog}.
For both, the core reason is a change in dependencies.
\textbf{Difference:} Although co-occur often, it is not guaranteed that dependency changes causing smells can always cause file movements.
For example, adding a dependency from file $f_1$ in component $C_1$ to $f_2$ in component $C_2$ would create a component-level dependency from $C_1$ to $C_2$, potentially forming a dependency cycle. 
However, such a single dependency might be strong enough to drive file movements. 
% For example, popular \ac{AS} detection tools like \ARCADE~\cite{schmittlaser_ARCADEExtensible_2020} and \Arcan~\cite{fontana_2017} mainly focus on dependency-related smells, such as dependency cycles, hub-like dependencies, and unstable dependencies.

Second, \acp{ADD} encompasses broad architectural concerns beyond smells, requiring maintainers to perform additional filtering to identify smell-inducing issues.

To validate these limitations, we conducted an empirical study comparing architectural change-related issues (captured by \RecovAr) with architectural smells detected by \ARCADE~\cite{schmittlaser_ARCADEExtensible_2020} on three open-source projects (detailed project descriptions in \autoref{sec:dataset}).
As shown in \autoref{fig:pre-study} and \autoref{tab:overlap}, for Inkscape, \RecovAr only captures 68.49\% of \ac{ASI} issues, missing 31.51\% of smell-inducing issues.
Furthermore, 79.20\% of architectural change-related issues recovered by \RecovAr are not smell-inducing, confirming the need for a more targeted approach. 
Similar patterns are observed across Shepard and StackGres.
Although \RecovAr does not miss smell-inducing issues, it contains 71.07\% and 65.47\% non-smell-related issues.

These findings motivate us to propose an approach to specifically identify \acl{ASI} issues rather than relying on general architectural change detection.
