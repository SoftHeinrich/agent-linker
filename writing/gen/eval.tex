\section{Experiment}
\label{sec:experiment}

We evaluate \approach{} on the public benchmark for trace links between architecture documentation and code.
The evaluation has four goals: see how \approach{} compares to existing tools, look at what new metrics tell us beyond the standard \fone, measure how much the validators help, and check what each linker agent contributes.

\subsection{Research Questions}
\label{sec:rqs}

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions]
    \item \label{RQ1 SOTA comparison} \emph{Does \approach{} recover better trace links than existing approaches, both from doc to architecture model and from doc to code?}
\end{enumerate}
\emph{\textbf{Motivation:}}
Trace links between an architecture document and code can be recovered directly, or in two steps through the architecture model.
Existing approaches use lexical similarity~\cite{swattr} or a single \ac{LLM} classification pass~\cite{lissa}.
\approach{} first builds runtime knowledge about the architecture (alias table, ambiguous names) and then runs several focused linker agents.
We want to know whether this extra structure pays off in both link tasks: doc-to-model and doc-to-code.

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions, resume]
    \item \label{RQ2 metrics} \emph{What do architecture-driven metrics tell us about the recovered links that the standard \fone does not?}
\end{enumerate}
\emph{\textbf{Motivation:}}
The standard evaluation reports one micro \fone\ over all sentence-target pairs at the link level.
On this benchmark, one human decision about a directory can expand into hundreds of link-level data points, so a few large components decide the score~\cite{replication}.
A single number can therefore hide whether a system covers all sentences, whether errors fall on small components, or whether developers would see noisy results.
We check if the metrics from \autoref{sec:metric} reveal these properties and reorder the systems.

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions, resume]
    \item \label{RQ3 validators} \emph{How much do the validators inside \approach{} contribute to the final result?}
\end{enumerate}
\emph{\textbf{Motivation:}}
\acp{LLM} are not deterministic and can produce links that look plausible but do not refer to any component in the doc.
\approach{} wraps each linker agent in one of two validation patterns (\autoref{tab:strategies}): voting between two \ac{LLM} passes for extraction agents, and asking for a quoted antecedent for the pronoun agent.
We measure how much these validators help, in \fone and in the new metrics.

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions, resume]
    \item \label{RQ4 ablation} \emph{What does each linker agent contribute on its own?}
\end{enumerate}
\emph{\textbf{Motivation:}}
\approach{} uses four linker agents, one for each kind of reference: canonical name, alias, pronoun, and partial name.
A leave-one-out ablation shows whether all four are needed, where they overlap, and which agents drive the gains over the best single-strategy baseline.

\subsection{Experiment Design}
\label{sec:exp-design}

To answer the four research questions we run four families of experiments on the same dataset (\autoref{sec:dataset}).
All \approach{} runs use a fixed model configuration (\autoref{sec:hyperparameters}) so results stay reproducible despite \ac{LLM} non-determinism.

\subsubsection{Experiments for \ref{RQ1 SOTA comparison} -- Comparison to Existing Approaches}
\label{sec:exp:rq1}

We run two evaluations on the same five projects (\autoref{sec:dataset}):
\begin{enumerate}[leftmargin=*]
    \item \emph{Doc-to-model.} For every sentence in the architecture document we recover the components it talks about and compare them with the doc-to-model gold standard. We compare \approach{} with \emph{SWATTR}~\cite{swattr}, the lexical NLP pipeline that TransArc uses for the doc-to-model step, and with \emph{LiSSA}~\cite{lissa}, a recent \ac{LLM}-based classifier. This is the link task where \approach{} can directly show what its knowledge layer is worth.
    \item \emph{Doc-to-code.} For every sentence we recover the code files it talks about and compare them with the link-level gold standard. \approach{} reaches code files by combining its doc-to-model links with the architecture model's component-to-file mapping, the same composition used by TransArc. We compare \approach{} with \emph{TransArc}~\cite{transarc}, the strongest published end-to-end pipeline on this benchmark, and with \emph{LiSSA} as an \ac{LLM} baseline.
\end{enumerate}
We take all baseline results from the original papers to avoid re-tuning bias.
For each task we report precision, recall, and \fone per project and averaged across projects (both macro and micro), following the protocol of the benchmark.
The outcome of \ref{RQ1 SOTA comparison} tells us whether \approach{} improves over existing tools on the link task it targets directly (doc-to-model) and on the downstream task that developers care about (doc-to-code).

\subsubsection{Experiments for \ref{RQ2 metrics} -- Architecture-Driven Metrics}
\label{sec:exp:rq2}

A pre-study (\autoref{sec:metric:prestudy}) motivates the metric suite from \autoref{sec:metric:suite}: two simple baselines---\emph{Random} and a structural \emph{Top-3} (one per task)---already trip up the standard link-level precision, recall, and \fone, while per-component \fone, sentence coverage, and noise rate catch them.
Here we apply the suite to \approach{} and the doc-to-code baselines (TransArc, LiSSA) from \ref{RQ1 SOTA comparison}, and to \approach{} and SWATTR for doc-to-model.
%TODO LiSSA placeholder: per-project link outputs for LiSSA are not in the replication package; either obtain them from the LiSSA authors and recompute the new metrics, or restrict the RQ2 comparison to AALinker vs TransArc/SWATTR and footnote the omission.

For each (system, project, task) cell we report the four primary metrics---link-level precision, recall, and \fone, per-component \fone, sentence coverage, and noise rate---per project and as macro means.
Per system we add two diagnostic views:
\begin{enumerate}[leftmargin=*]
    \item a \emph{per-component \fone\ distribution}, showing which components are fully covered, which are uncovered, and where false-positive and false-negative mass piles up;
    \item a \emph{per-sentence coverage--noise scatter}, splitting gold sentences into served-cleanly, served-noisily, and unserved, with the share of each reported per system.
\end{enumerate}
Across systems and projects we report the rank correlation between the standard link-level \fone\ and each new metric.
A metric that reorders the systems shows something that the standard \fone\ does not.
The appendix reports per-sentence \fone, the coverage--purity composite, and the skill score, with a redundancy analysis showing they do not change the ranking conclusions.

\emph{\textbf{Expected outcome.}}
We commit to two falsifiable predictions:
\begin{enumerate*}[label=(\roman*)]
    \item per-component \fone\ reorders systems compared to the standard link-level \fone, because the latter is dominated by a few large components;
    \item sentence coverage and noise rate vary independently of \fone---two systems with similar \fone\ can show very different coverage and noise.
\end{enumerate*}
The outcome of \ref{RQ2 metrics} is the table of (system, metric, project) values, the diagnostic plots, the rank correlations, and a verdict on each prediction.

\subsubsection{Experiments for \ref{RQ4 ablation} -- Per-Agent Ablation}
\label{sec:exp:rq4}

We measure each linker agent by leave-one-out ablation: \emph{$-$Explicit},
\emph{$-$Contextual}, \emph{$-$Anaphoric}. 
The knowledge layer (\autoref{sec:approach}) stays in place in every run, because all four
agents read from it. 
%overhaul, we do not report those metrics, but report fp,tp percentage and overlap among linkers, or other better approach, design for that
For each variant we report:
\begin{enumerate*}[label=(\roman*)] \item the change in macro \fone over the
five projects, \item the change in sentence coverage and noise rate, which tells
us whether the removed agent added recall or only filtered false positives, and
\item how many true positives are lost that no other agent recovers.
\end{enumerate*} We also report \emph{Explicit-only}, a single-agent baseline
that the other agents extend on top of. This experiment shows whether the four
reference categories really need separate agents, or whether one agent already
covers the others on this benchmark.

\subsection{Dataset}
\label{sec:dataset}

We use the public benchmark released with TransArc~\cite{transarc,replication}.
It contains five Java open-source systems with hand-curated architecture docs, an architecture model, and a gold standard at two grains, sentence-to-component and sentence-to-file:
\emph{MediaStore}, \emph{TeaStore}, \emph{Teammates}, \emph{BigBlueButton}, and \emph{JabRef}.
We use this benchmark because it is the standard evaluation set for this task~\cite{transarc,lissa} and because it gives us gold links at both granularities, which we need for both \ref{RQ1 SOTA comparison} (doc-to-model and doc-to-code) and \ref{RQ2 metrics}.

\input{table/dataset-stat}

\autoref{tab:dataset} lists, per project, the number of sentences in the architecture document, the number of components in the architecture model, the number of code files, the number of human gold decisions, and the number of link-level pairs after each directory decision is expanded to its files.
The expansion factor differs by two orders of magnitude across projects (1.0$\times$ for MediaStore, 217.6$\times$ for JabRef).
This is one of the reasons we report the extra metrics in \ref{RQ2 metrics}.

For each project we use the architecture document as input~$D$, the architecture model as the component set~$C$, and the gold standard as the ground-truth links between sentences of~$D$ and components of~$C$ (or files belonging to components of~$C$, for the doc-to-code task).
We use the official benchmark loaders for $D$ and $C$ to stay aligned with prior work.

\subsection{Replication}
\label{sec:replication}

All prompts, agent code, ablation configurations, raw \ac{LLM} responses, and per-project result CSVs are in our replication package~\cite{replication}.
The package also contains the implementations of the metrics used in \ref{RQ2 metrics} so that anyone can reproduce the evaluation and apply the same metrics to other approaches on the same benchmark.
