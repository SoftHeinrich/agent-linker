2 How we prompt — the facts are computed, the reading is asked

No rule decides in advance which sentences carry a reference: every sentence goes to the model as a case, in batches of ten, with a ±5-sentence window of the document around it — for a 13-sentence document, the whole text. What the prompt does not leave open is the antecedent search space. For each case the code computes NAMED BEFORE THIS CASE — the components the sentences above it actually name, each with the sentence that names it, nearest first — using the same exact name relation the rest of the workflow reads names with. That list is a prior, not a constraint: the model may answer outside it, and the code checks the sentence numbers it reports, not its membership.

The division of labourper case

code  Which components the earlier sentences name. A fact, settled exactly by the name relation plus the alias table — no model is asked for it, and no model can get it wrong. For case 7 the code is right: preferences really is named, in S2.

LLM  Which reading a referring expression carries in its sentence. This is in no table. It is the one judgement only the model can make — and case 7 is where it goes wrong, exactly as the motivating example predicts.

The shortlist is a prior, not a filter. The code validates the two sentence numbers the reply reports against the document — an invented sentence cannot name a real one — and does not require the answer to be a member of the list.

3 The evidence bundle — what the coreference judge is shown

The judge does not re-do the resolution; it rules on the commitment the resolver already made. So the bundle is not the computed mention bundle the two name judges receive — a coreference case has no name surface to anchor. It is the resolver’s own two commitments, carried forward verbatim, plus the sentence in its immediate context. Withholding them is expensive: an earlier arm that handed the judge only a sentence and a component name made it guess which expression was claimed to refer and to what, and it rejected about half the gold resolutions put to it (49.8 % kept).

rubric — strict, because the name is absentThese are coreference links: a pronoun or noun phrase in the sentence is
claimed to refer back to the component, which is NOT named in the sentence
itself. Approve only when the sentence contains a genuine referring
expression that unambiguously points to THIS component and makes an
architectural claim about it. Reject when there is no such referring
expression or when the antecedent could equally be a different component.
An expression denoting what a component acts on or produces refers to that
thing and not to the component, however clearly the component is the one
acting on it. When uncertain, reject.

is one the rules above make decisive. An objection you could raise against
most sentences is not a ground for rejecting this one.

The motivating example’s false positive, in the system’s own wordscase B

The motivation states the failure as a word matches the wrong component. The judge rejects it with the same distinction, unprompted by any list of words: the bolded clause of the rubric is a general rule about denotation, not a stop-list, and nothing in the module names preferences or any other project term.

The same false link is proposed twice on this document, by two independent routes, and refused twice: the full-name linker proposes S7 → preferences because the word matches, and its judge returns claim: none; the coreference resolver proposes it as a refer-back, and its judge returns the objection above.

Why the objection field. The strict rubric asks for the strongest ground against the link before the verdict, then discounts objections that would fire on most sentences. On this document that field is the whole of the stage’s contribution: it writes down, case by case, why five of six proposed resolutions do not hold.

Read as a whole system the row is low — but that is scope, not quality: the stage fires only on sentences carrying a referring expression, so scoring it against the entire gold standard charges it for every sentence it was never meant to see. Removing it costs 4.6 pp of link-level F1, yet it is what reaches components a document never names twice: dropping both small linkers takes worst-component F1 from 0.81 to 0.70 and harmonic per-component F1 from 0.93 to 0.86.

The stage in one line. Exactly one question is put to the model — what does this expression refer to — on a shortlist the code has already settled; the judge then rules on the resolver’s own quoted commitment rather than re-reading the sentence. On JabRef that machinery spends itself refusing, including on the very false positive the motivating example is built from; on documents whose components are not named twice it is the only route to the link.
