1 Input — a sentence that names no component

The linker sees the documentation text, the component catalogue, and the alias table the knowledge module learned from this document. Sentence 24 states an architectural fact about a component but contains no component name, no alias, and no name part: every name-matching relation in the workflow returns nothing on it.

2 LLM 1 — resolver prompt: the facts are computed, the reading is asked

No rule decides in advance which sentences carry a reference: every sentence goes to the model as a case, in batches of ten, with a ±5-sentence window of the document around it. What the prompt does not leave open is the antecedent search space. For each case the code computes NAMED BEFORE THIS CASE — the components the sentences above it actually name, each with the sentence that names it, nearest first — using the same exact name relation the rest of the workflow reads names with. That list is a prior, not a constraint: the model may answer outside it, and the code checks the sentence numbers it reports, not its membership.

The division of labourper case

code  Which components the earlier sentences name. A fact, settled exactly by the name relation plus the alias table — no model is asked for it, and no model can get it wrong.

LLM  Which reading a referring expression carries in its sentence. This is in no table. It is the one judgement only the model can make, and it is where the coreference linker does its real work.

The shortlist is a prior, not a filter. The code validates the two sentence numbers the reply reports against the document — an invented sentence cannot name a real one — and does not require the answer to be a member of the list.

3 LLM 2 — judge prompt: the resolver’s real fields are carried forward

The resolver response has seven fields: case, sentence, reference, candidates, component, antecedent_sentence, and antecedent_text. The implementation validates the reported sentence numbers, then builds the judge case from the resolved component, reference, antecedent sentence and text, and the target sentence with its predecessor. The judge therefore rules on the resolver’s actual commitment instead of reconstructing one.

LLM 2 prompt and response — judge case 51 call / 25 cases
questionValidate components in a document. Check coref resolution: does the
referring expression in this sentence actually refer to the named
component as an architectural participant?

rubric — strict, because the name is absentThese are coreference links: a pronoun or noun phrase in the sentence is
claimed to refer back to the component, which is NOT named in the sentence
itself. Approve only when the sentence contains a genuine referring
expression that unambiguously points to THIS component and makes an
architectural claim about it. Reject when there is no such referring
expression or when the antecedent could equally be a different component.
An expression denoting what a component acts on or produces refers to that
thing and not to the component, however clearly the component is the one
acting on it. When uncertain, reject.

reply contract — quote, then object, then decidefirst quote the EXACT words from the sentence that state the architectural
claim …, then state the strongest ground there is for rejecting this case
under the rules above (or "none"), then decide: approve unless that ground
is one the rules above make decisive. An objection you could raise against
most sentences is not a ground for rejecting this one.

Why the objection field. The strict rubric asks for the strongest ground against the link before the verdict, and then discounts objections that would fire on most sentences. On this document that field is what kills the three false resolutions — and, as stage 4 shows, it also fires on two links that were true but that another linker already holds.

Read as a whole system the row is low — but that is scope, not quality: the stage fires only on sentences carrying a referring expression, so scoring it against the entire gold standard charges it for every sentence it was never meant to see. On the sentences it does answer it is the most precise proposer in the workflow. Removing it costs only 4.6 pp of link-level F1, yet it is what reaches the components a document never names twice: dropping both small linkers takes worst-component F1 from 0.81 to 0.70 and harmonic per-component F1 from 0.93 to 0.86.

The stage in one line. Exactly one question is put to the model — what does this expression refer to — on a shortlist the code has already settled; the judge then rules on the resolver’s own quoted commitment rather than re-reading the sentence; and the links that survive are few, almost entirely true, and reachable by no other route.
