We study four research questions:
\subsection{Research Questions}

% RQ1 Can the multi-stage LLM workflow outperform SOTA approach?
% \emph{\textbf{Motivation:}}

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:,
ref=RQ\arabic*, series=researchQuestions] \item \label{rq:sota}
\emph{Does \approach recover trace links better than existing approaches?} 
\end{enumerate}
\emph{\textbf{Motivation:}}
Existing approaches either match component names lexically~\cite{keim_trace_2021} or classify with a single \ac{LLM} call~\cite{fuchs_whos_2025}. 
\approach first builds runtime knowledge about the architecture and then runs three focused linker modules with \evidenceBacked judges.
We want to know whether this extra structure helps in both link recovery tasks: doc-model, and its downstream task doc-code.

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions, resume]
    \item \label{rq:metrics} \emph{What do architecture-driven metrics tell us about the recovered links that the standard link-level metrics do not?}
\end{enumerate}
\emph{\textbf{Motivation:}}
The standard evaluation averages precision, recall, and \fone\ over all benchmark links.
This average is dominated by a few large components, hiding whether a system covers every sentence or drops small components.
We check whether the architecture-driven metrics expose these properties and reorder the systems.

% RQ3 whats the contribution of validators in our approach?
% \emph{\textbf{Motivation:}}

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions, resume]
    \item \label{rq:validators} \emph{How much do the judges inside \approach contribute to the final result?}
\end{enumerate}
\emph{\textbf{Motivation:}}
\acp{LLM} hallucinate: a linker can return a link that looks plausible but does not hold up under inspection.
\approach{} wraps each linker in its corresponding \evidenceBacked judge.
We measure how much each check helps by calculating the confusion matrix.

% RQ4 ablation, whas the contribution of each sub-linker module?
% \emph{\textbf{Motivation:}}

\begin{enumerate}[leftmargin=*, labelindent=0em, label=\textbf{RQ\arabic*}:, ref=RQ\arabic*, series=researchQuestions, resume]
    \item \label{rq:ablation} \emph{What does each module of \approach{} contribute on its own?}
\end{enumerate}
\emph{\textbf{Motivation:}}
\approach{} splits the linking work by \emph{evidence form}---a whole name, one word of a name, or a referring expression---and gives each form the proposer that form admits and a judge of its own, over one shared knowledge module.
Whether that decomposition pays is a different question from whether the judges pay (\ref{rq:validators}): a judge can only remove links, whereas the form decides which links exist to remove.
A module-level ablation prices each form, and the knowledge they share, separately.

\subsection{Experiment Design}
\label{sec:exp-design}

To answer the four research questions we run four families of experiments on the the \ardoco benchmark, the largest benchmark to the best of our knowledge~\cite{fuchs_establishing_2023}.

All baselines are run with their authors' released configurations, with one
deliberate exception: \Artemis{} is an \ac{LLM} pipeline, so we re-run it on
GPT-5.6-terra, the backend \approach{} uses, changing nothing but the model id.

released GPT-5.4 arm is reported alongside in the appendix.

For each task, we run both \ac{LLM} systems---\approach{} and the re-run \Artemis{}---three times and report the mean, so neither is credited with a lucky draw; the deterministic baselines are run once.
To avoid depending on one model, we run \approach{} on two language-model backends, GPT-5.6-terra and GPT-5.6-luna; the body reports terra and the appendix mirrors every table on luna.

\subsubsection{Experiments for \ref{rq:sota}}
\label{sec:exp:rq1}

Doc-code is the downstream task of doc-model: following prior work~\cite{fuchs_whos_2025,keim_recovering_2024}, \approach{} recovers the doc-model links first, then composes them into code links.
The two evaluations are:
\begin{enumerate}[leftmargin=*]
    \item \emph{Doc-model.} For every sentence in the architecture document, we use \approach to link it back to architectural components.
     We then compare recovered links with the doc-model gold standard links. 
    We compare \approach{} with two baselines: \emph{SWATTR}~\cite{keim_trace_2021}, a lexical string-similarity pipeline; and \Artemis{}~\cite{fuchs_whos_2025}, an \ac{LLM} entity-recognition tool for the same task.

    %  (heuristic) and \Artemis{} composed through the same file mapping on doc-code -- three
    %  distinct families across the two grains, and \Artemis{} is backend-matched, which is the
    %  stronger answer to "not enough baselines" than a fourth weak system would be.
    %  NOT run: LiSSA~\cite{fuchs_lissa_2025} and a VSM/IR baseline. LiSSA is already cited in

    %  only if a reviewer asks; do not add VSM (\TransArc{} already covers non-\ac{LLM}).
    This is the link task where \approach{} can directly show its strength.
    \item \emph{Doc-code.} For every sentence we recover the code files it talks about and compare them with the link-level gold standard. 
    \approach{} reaches code files by transitive linking, the same composition used by \TransArc{}.
    It combines its doc-model links with the architecture model's component-to-file link recovery via ArCoTL~\cite{keim_recovering_2024}. 
    We compare \approach{} with two baselines: \TransArc{}~\cite{keim_recovering_2024}, the strongest heuristic-based approach; and \Artemis{} composed through the same \TransArc{} file mapping, as an \ac{LLM} baseline at the doc-code grain.
\end{enumerate}
For each task we use the same metrics \TransArc{} and \Artemis{} use.
We report link level precision, recall, and \fone per project and averaged across projects.
We report \ftwo\ beside \fone\ throughout: a spurious link is visible to the developer who reads it, while a link the system never proposes is not, so recall and precision are not equally costly here.
The outcome of \ref{rq:sota} tells us whether \approach{} improves over existing tools on the link task it targets directly (doc-model) and on the downstream task that developers care about (doc-code).


\subsubsection{Experiments for \ref{rq:metrics}}
\label{sec:exp:rq2}
\ref{rq:sota} scores every system with the standard link-level metrics.
The pre-study (\autoref{sec:metric:prestudy}) shows these metrics are limited because of the benchmark's extreme inequality.
\ref{rq:metrics} re-runs the same comparisons under the metric suite of \autoref{sec:metric:suite}.

%DONE, \cmr is justified within the suite, so this reads as "apply the suite" and nothing
%  more. \cmr is the doc-model-only size-aware metric; it is not used on the file grain.
For each (system, project) cell on the doc-code task we compute the \fone-tail of the suite: reference link-level \fone\ and the two component-size aware metrics (worst-component and harmonic-mean per-component \fone).
On the doc-model task, we instead report the \cmrname{} (\cmr, \autoref{eq:cmr}), the share of gold sentence--component assignments whose component a system abandons.
We read the size-aware metrics beside link-level \fone: where a system scores well on the standard metric yet poorly on the size-aware ones, it has recovered the bulk of the links while leaving whole components untraced.

\subsubsection{Experiments for \ref{rq:validators}}
\label{sec:exp:rq3}
We build four ablations of \approach{} that remove judges, one per judge plus the union.
Running on the same benchmark, we compare each ablation against \emph{\fullVariant{}}, the full pipeline.

\begin{enumerate}[leftmargin=*]
\item \emph{\noEntityValid{}}: skip the \entValidator{} (\autoref{sec:validators}); accept all candidates from \linkerB{} without the
\entValidator{}.

\item \emph{\noPartialValid{}}: skip the \partValidator{}; accept all candidates from \linkerD{} without the \partValidator{}.

\item \emph{\noCitation{}}: skip the \corefValidator{}; accept all implicit-reference candidates without \corefValidator{}.

\item \emph{\noValidator{}}: skip all three judges (the three above combined).
\end{enumerate}
Each judge logs a verdict per candidate it sees, so we read the ablations off the full pipeline's own decision log rather than re-running it three times.

\subsubsection{Experiments for \ref{rq:ablation}}
\label{sec:exp:rq4}
We ablate \approach{} at the module level.
The workflow has four modules: the knowledge module and the three linker modules \linkerB{}, \linkerD{}, and \linkerC{}.
We measure their contributions with different methods.
For each linker we score the links it alone kept, and we measure it by set overlap, decomposing the gold links it catches into the ones no other linker catches and the ones at least two share.
This reports how many true positives each linker contributes that the others do not.
For the knowledge module we run a leave-one-out variant: we switch off the document-alias stage, re-run every linker on canonical component names only, and compare against the full workflow over the same three runs.
This isolates how much of the gain comes from the shared knowledge rather than from the linkers themselves.
\autoref{tab:rq4} reports the size-aware suite for the full workflow, for each linker on its own, and for the no-knowledge variant.

Wherever a linker proposes by scanning, \ref{rq:validators} and \ref{rq:ablation} bound the same candidate set from opposite sides, which is why we report both.
Switching a judge off accepts every pair its linker proposes, switching the linker off accepts none, and \approach{} sits where the judge cuts in between.
The proposer therefore fixes the recall ceiling and the judge fixes where precision lands beneath it---two quantities that neither ablation gives on its own.
