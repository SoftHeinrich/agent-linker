The document usually names components descriptively: "the API server" / "apiserver" is kube-apiserver, "the scheduler" is kube-scheduler, "the controller manager" is kube-controller-manager, "the cloud controller manager" is cloud-controller-manager, "the container runtime" (containerd, CRI-O, ...) is container-runtime. "The control plane" as a whole, "a node", "a Pod", "a controller" in general and the Kubernetes API as a concept are not components.
