## Methodological Contributions

1. **Probe-wave methodology validated as a milestone-scoping mechanism.** Four cheap parallel probes (~$3) cut decisively across 4 mechanism pillars in one day, replacing what the original v2.2-MILESTONE-PROPOSAL planned as a 5-phase exploration (~20 plans). Cost-effective feasibility screening before committing to full Range testing.

2. **Per-backend cache-key methodology for runtime LLM rubrics** — per-(text_stem, comp_hash, backend, model) cache key. Unblocks fair cross-model comparison of runtime-rubric mechanisms. The Range D Claude FAIL was indistinguishable from a true cross-model failure until the cache-key fix isolated cross-backend rubric reuse as a confound. Now a v2.3 prereq.

3. **Probe A' vocab-aligned R3** — discourse/syntactic vocabulary (subject-position, anaphora, qualifier clause, namespace prefix, ...) replaces textbook SE vocabulary, narrowing the R3/R5 vocabulary deadlock that falsified original Probe A. Narrows but does not eliminate the v4 architecture challenge (BBB still inactive). Surfaces a "v4 mechanism is dataset-conditional" finding.

4. **GATE-08 cost-per-improvement audit** — introduced in v2.2 scope decision and applied to Probe C (WEAK_PASS +0.00004pp, doubled judge cost). Carried to v2.3 as a standing audit gate for runtime mechanisms with marginal gain.

## Findings (publishable)

1. **Probe D (upstream coref rubric)**: runtime per-dataset coref rubric replaces static `COREF_RULES` with gpt-5.4 lift (+1.59pp mediastore matching Claude baseline; mean +2.2pp BBB over 2 observations). Generalizes the trim9 mechanism class (Phase 12 Plan 12-12) from seed tier to coref tier. Cross-backend transfer not confirmed (Claude was cache-confounded; methodologically unblocked).

2. **Probe B (preamble+rubric)**: LLM-built per-dataset alias-judge rubric introduced an over-aggressive token-reject rule producing 4 FNs vs anchor's 1 → -5.24pp. Failure mode: cold-generated per-dataset rubrics over-restrict at scale. Contrasts with trim9/Probe D which replace narrow rules (seed disambiguation, coref) rather than the full judge rubric.

3. **Probe C (Self-Refine)**: 2-iter Self-Refine matched anchor exactly (+0.00004pp); 80% iter-0 contested rate but iter-1 fired without changing the approved set → judge at ceiling. GATE-08 cost flag. Ceiling effect is a published finding: the alias judge in `s_linker13_min` has near-zero residual error on mediastore, making self-refinement vacuous on that dataset.

4. **Probe A (Voyager v4 original)**: R3/R5 vocabulary deadlock — textbook SE vocabulary (controller, scheduler, broker, queue) is rejected by R5's 5-style transferability test as "style-dependent" → 100% R5 reject → falsification of v4 with that vocabulary. Published as a vocabulary-alignment finding for multi-role training architectures.

5. **Probe A' (vocab fix)**: R3 narrowed to discourse/syntactic terms → mediastore STRONG_PASS (+1.69pp) but BBB WEAK_PASS (R5 0/8, F1 -0.24pp) → v4 architecture is dataset-conditional, not universally promotable. The validated patterns don't translate into BBB-recoverable inference behavior (downstream-utility gap, not vocab-alignment failure).

6. **Cross-backend cache reuse confounds runtime-rubric cross-model tests.** The per-backend cache-key fix (per-(text_stem, comp_hash, backend, model)) is a methodological prerequisite for any future cross-model evaluation of runtime LLM rubrics. Without it, cross-backend rubric reuse is silently indistinguishable from a true cross-model failure.
