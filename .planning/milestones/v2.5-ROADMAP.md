## v2.5 Goal

Fix the two remaining v2.4 infrastructure bugs (oracle cache contamination at line 455 + probation min-commit threshold too loose) and expand Voyager training scope from 9→15 axiom slots by wiring `ilinker3.py` and `s_linker14_voyager.py` static prompts as bank-injectable slots, then re-run the full 3-split Confirmation sweep to measure the true approach ceiling with clean infrastructure.

**Canonical baseline going in**: `s_linker13_min` (Claude macro 0.9506, gpt-5.4 macro 0.9069). Unchanged throughout v2.5.

**Outcome verdict options:**
- **STRONG (≥ 0.9173):** `s_linker14_voyager` promoted with cross-split evidence; 15-slot architecture validated as production-grade.
- **WEAK ([0.87, 0.9173)):** Ships with documented caveat; oracle fix + slot expansion documented as research finding; gap analysis for v2.6.
- **FAIL (< 0.87):** Training infrastructure fundamentally blocked — publish negative finding with root-cause.

`s_linker13_min` retains `canonical=True` throughout regardless of outcome.

## Phase Details

### Phase 25: Infrastructure Fixes

**Goal**: The two remaining v2.4 infrastructure bugs are eliminated in code — oracle cache now includes `bank_content_hash` in the key (preventing cross-split oracle reuse when bank state differs), probation min-commit threshold raised to `delta >= 0.005` (filtering ±3–4pp BBB LLM variance), and D prompt steers proposal effort toward empty slots — so that subsequent training runs consume clean infrastructure.
**Depends on**: Nothing (first phase of v2.5; v2.4 shipped).
**Requirements**: REQ-V25-01, REQ-V25-02, REQ-V25-03
**Success Criteria** (what must be TRUE):
  1. Oracle cache key in `voyager_train_tlr_v4_beta.py` line 455 includes `bch = _bank_content_hash(bank)`, matching the pattern already used by the L cache; existing oracle cache files are correctly invalidated on bank state change.
  2. Probation accepts only patterns with `delta >= 0.005`; a pattern that produces a 0.003 F1 delta on a BBB-containing split is rejected without extra LLM calls.
  3. D prompt displays per-slot pattern counts AND lists zero-pattern slots by name as high-priority proposal targets; a training run where ENTITY_EXTRACTION_RULES has zero patterns includes it in the D prompt's "underfilled" list.
  4. GATE-06 check passes on all prompt text changes in this phase (no benchmark vocabulary introduced).
  5. Frozen artifacts (`s_linker13.py`, `prompts_v2.py`, `ilinker*.py`, `data_types_v2.py`, `document_loader_v2.py`, `pcm_parser_v2.py`, `s_linker13_min.py`) are byte-equal to their v2.4 state; no plan in this phase modifies them.

### Phase 26: 15-Slot Expansion

**Goal**: The Voyager training bank expands from 9 to 15 injectable slots — 6 new slot constants defined in `prompts_v3_axiom.py`, `ilinker3.py` behavior exposed as bank-injectable via `ILinker3Injected` subclass in `s_linker14_voyager.py`, four inline static prompt strings in `s_linker14_voyager.py` replaced by slot-backed f-string injection, harness updated to recognize all 15 slots, and `AMBIGUITY_FEW_SHOT` / `DOC_KNOWLEDGE_JUDGE_EXAMPLES` populated with GATE-06-clean seed examples — so that the training re-run can discover and commit patterns across the full 15-slot surface.
**Depends on**: Phase 25 (infrastructure must be clean before expansion is wired in)
**Requirements**: REQ-V25-04, REQ-V25-05, REQ-V25-06, REQ-V25-07, REQ-V25-08
**Success Criteria** (what must be TRUE):
  1. `prompts_v3_axiom.py` exports exactly 15 slot constants; the 6 new slots (`SEED_EXTRACTION_RULES`, `SEED_ACTOR_RULES`, `GENERIC_WORD_USAGE_RULES`, `ALIAS_SCOPE_RULES`, `ANTECEDENT_ALIAS_RULES`, `COREF_TERMINAL_SPECIFICITY_RULES`) default to empty string; running `s_linker14_voyager` with all new slots empty produces output byte-equal to the v2.4 baseline.
  2. `s_linker14_voyager.py` contains an `ILinker3Injected` subclass that overrides `_prompt_extract()` and `_prompt_actor()`; `ilinker3.py` is byte-equal to its v2.4 state; injecting a non-empty `SEED_EXTRACTION_RULES` string prepends it to the extraction prompt.
  3. Four inline prompt strings in `s_linker14_voyager.py` are replaced by slot-backed injection; each slot's empty-string fallback produces behavior identical to the prior hardcoded text.
  4. Training harness `voyager_train_tlr_v4_beta.py` Oracle `failure_modes` schema and Distillator proposal schema both list all 15 slot names; per-project candidate bank initialized with 15 keys; D prompt flags new zero-pattern slots.
  5. `AMBIGUITY_FEW_SHOT` and `DOC_KNOWLEDGE_JUDGE_EXAMPLES` each contain ≥ 2 abstract seed examples that pass GATE-06 grep (no benchmark component names, no project-specific vocabulary from `BENCHMARK_TABOO.md`).
  6. Frozen artifacts (`s_linker13.py`, `prompts_v2.py`, `ilinker*.py`, `data_types_v2.py`, `document_loader_v2.py`, `pcm_parser_v2.py`, `s_linker13_min.py`) are byte-equal to their Phase 25 state; no plan in this phase modifies them.
