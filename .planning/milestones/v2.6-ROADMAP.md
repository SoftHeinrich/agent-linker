## v2.6 Goal

Replace the mechanical training gate (Gate A + Gate B F1-delta checks) with an LLM Assessor that reasons over the actual remaining FP/FN error sets; build `ilinker4.py` as a Voyager-native seed extractor where `SEED_EXTRACTION_RULES` and `SEED_ACTOR_RULES` are first-class bank slots (not inline rules); fix the 3 identified axiom vocabulary gaps (SCN 14 FNs, gerund FPs 7, coref alias code path); and re-run the full training tier sequence against a cleaner, smarter training loop.

**Target**: exceed canonical `s_linker13_min` gpt-5.4 macro F1 of 90.69%.

**Canonical baseline going in**: `s_linker13_min` (Claude macro 0.9506, gpt-5.4 macro 0.9069). Unchanged throughout v2.6.

**v2.5 baseline for comparison**: WEAK — cross-split macro F1 89.1% (gpt-5.4, 5-dataset, 12-pattern bank).

**Outcome verdict options (training tiers):**
- **STRONG (≥ 0.9173):** `s_linker14_voyager` promoted with cross-split evidence; LLM Assessor + ILinker4 architecture validated as production-grade.
- **WEAK ([0.87, 0.9173)):** Ships with documented caveat; LLM Assessor + axiom fixes documented as research finding; gap analysis for v2.7.
- **FAIL (< 0.87):** Training infrastructure or LLM Assessor fundamentally blocked — publish negative finding with root-cause.

`s_linker13_min` retains `canonical=True` throughout regardless of outcome.

### Phase 32: LLM-Driven Training Loop (v5)

**Goal**: The Voyager v5 training harness exists with (a) Oracle and Distillator merged into a single text-aware `OD` role that diagnoses errors and proposes patterns in one call, (b) an LLM Assessor replacing Gate A + Gate B entirely with accept/reject/revise verdicts based on FP/FN sentence evidence, (c) independent per-split evaluation where each split trains on its own train set and is evaluated against an axiom-only baseline on its own held-out test set, and (d) [TRAIN]/[TEST] log separation in all training output — so that the training tier (Phase 34–36) runs on a loop that reasons about errors rather than compares F1 deltas.
**Depends on**: Phase 31 (ILinker4 wired; SEED slots active)
**Requirements**: REQ-V26-03, REQ-V26-04, REQ-V26-05, REQ-V26-06, REQ-V26-07
**Success Criteria** (what must be TRUE):
  1. A single `OD` LLM role per project receives the current bank, FP sentence list, FN sentence list, and gold standard; in one call it outputs (a) identified failure modes with labels and (b) proposed bank patterns with slot assignments and abstract/general vocabulary; the prior separate Oracle and Distillator calls are removed.
  2. LLM Assessor receives each proposed pattern text + slot, the full current bank, and the remaining FP/FN sentence lists with component context; its output is one of `accept`, `reject`, or `revise` with a rationale that identifies specific FP or FN sentences addressed; Gate A and Gate B F1-delta checks are removed from the code path; max 1 revision cycle per proposal is enforced.
  3. Each split trains independently on its train-set projects; at pass completion, the trained bank is evaluated against an axiom-only baseline run on the same held-out test set; the verdict question per split is "does training on {train_set} improve F1 on {test_set} beyond axiom-only?"; no cross-split aggregation or dedup occurs during training.
  4. Every training log entry includes both `[TRAIN] {project}: F1=x ... macro=x` and `[TEST] {project}: F1=x ... macro=x` lines per pass; the commit-decision delta uses [TRAIN] macro only; [TEST] is logged but does not gate commits.
  5. GATE-01 regression test: running `s_linker13_min` with no bank changes still yields Claude macro ≥ 0.9506 and gpt-5.4 macro ≥ 0.9069; the harness changes do not touch `s_linker13_min` in any way.

### Phase 33: Axiom Gap Fixes

**Goal**: The three identified axiom vocabulary gaps are closed: (1) `COREF_RULES` or `DOC_KNOWLEDGE_EXTRACTION_RULES` instructs the LLM to link role-referential definite NPs to their section-established component referents (SCN gap, 14 FNs); (2) `SEED_DISAMBIGUATION_RULES` instructs the LLM to reject bare gerund/nominal fragments describing a component's own capabilities without an external participant (gerund FP gap, 7 FPs); (3) `COREF_RULES` or `ANTECEDENT_ALIAS_RULES` instructs the LLM to set `antecedent_via_alias=True` when the antecedent sentence contains a known alias (coref alias gap, activating the existing code path at line 1004) — with zero regression on safe datasets confirming the fixes are general-purpose.
**Depends on**: Phase 32 (v5 loop must be in place before axiom baseline is established)
**Requirements**: REQ-V26-08, REQ-V26-09, REQ-V26-10, REQ-V26-07
**Success Criteria** (what must be TRUE):
  1. Gap 1 (SCN): the relevant axiom slot (`COREF_RULES` or `DOC_KNOWLEDGE_EXTRACTION_RULES`) includes a semantic/intent-level instruction for role-referential definite NPs; zero regression on MS/TS/JAB gold links confirmed by running `s_linker14_voyager` with the updated axiom on those three datasets.
  2. Gap 2 (gerunds): `SEED_DISAMBIGUATION_RULES` includes an instruction that rejects bare gerund/nominal fragments describing a component's own capabilities; the rule explicitly preserves cross-component gerund references; zero regression on MS/TS gold links confirmed by targeted evaluation.
  3. Gap 3 (coref alias): the relevant axiom slot includes an instruction to set `antecedent_via_alias=True` when the antecedent sentence contains a known alias of the component; the existing code branch at `s_linker14_voyager.py:1004` is exercised; BBB pronoun sentences remain FP-free after the change.
  4. All three axiom changes are text-only modifications to axiom slot constants; no new code paths are introduced beyond the Gap 3 alias flag (which uses the existing branch at line 1004).
  5. GATE-06 check passes on all axiom text changes (no benchmark vocabulary; rules framed in discourse/semantic/functional terminology, not project component names).
