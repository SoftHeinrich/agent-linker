## Key Findings

**1. Gate fix is operational.** Phase 22 Phase 23 gate behavior: Pass 1 and Pass 5 of Phase 22 correctly rolled back (delta −0.0066, −0.0036). All 5 split-2 passes correctly rolled back. No false commits. Gate A and Gate B implementation validated as correct.

**2. REQ-V24-01 empirical target FAIL — root cause revised.** v2.3 attributed split-2 empty bank to broken probation gate. v2.4 shows the fixed gate also produces split-2 0/5 commits. However, post-hoc infrastructure investigation found the D cache collision (see §3) meant split-2 never received BBB-tailored distillation. The causal chain is: D cache bug → all splits get identical proposals → proposals don't address BBB-specific failures → probation delta < 0 → rollback. The gate is innocent; the upstream D was compromised.

**3. D cache collision invalidates cross-split diversity (post-hoc finding).** The distillator cache key used `prompt[:200]` — truncated before oracle data appears in the template. All 3 splits at each pass number shared one cached D output (`d_iter{N}...f876ef8d`). The 3 splits × 5 passes = 15 D calls produced only 5 unique distillations. Split-2 never received BBB-specific proposals; split-3 didn't receive TS+TM+JAB-specific proposals. The ≥2-split survival filter was measuring agreement across splits that received identical proposals, not genuine cross-split consensus. **This bug is fixed in current script** (line 664: full `md5(prompt.encode())`).

**4. Oracle cache contamination.** Oracle key has no bank state; split-3 TM got mainline oracle outputs (F1=0.8264) when split-3 actual TM F1 was 0.7874. **Not yet fixed** (line 455). Fix: add `bank_content_hash` to oracle key.

**5. Axiom improvements (D-2/D-3) show zero net effect.** Cross-split result is 90.5% — identical to v2.3 Phase 17. SCN anaphoric extension and gerund rejection did not yield additional cross-split consensus patterns. This is partly attributable to the D cache collision masking any differentiated benefit.

**6. ENTITY_EXTRACTION_RULES never proposed.** Despite BBB having 10+ missed exact-match extractions per pass, D proposed DOC_KNOWLEDGE_EXTRACTION_RULES 5/5 passes and never ENTITY_EXTRACTION_RULES. Slot steering gap.

**7. True ceiling unknown.** With D cache fixed and oracle cache fixed, a clean v2.5 re-run could yield substantially different results. The v2.4 WEAK verdict cannot be taken as the approach ceiling.
