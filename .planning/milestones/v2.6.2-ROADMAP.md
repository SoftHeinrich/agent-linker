## Thesis

**Unify the two-pipeline structure (ILinker4 seed + alias-aware entity pipeline) into a
single Multi-Framing Extraction design** suitable for a clean ICSE paper story.

Background: s_linker15 (v2.6.1) exposes two conceptually separate extraction sub-pipelines —
(A+B) the ILinker4 seed pass, and (C) the alias-aware entity extraction pass — that both solve the
same NLP task. The separation is an execution-order artifact, not a conceptual distinction. For
ICSE, this reads as implementation complexity. Two variants are evaluated:

- **s_linker17a** — rename-only. Current s15 architecture relabelled as Framing A/B (ILinker4 seed)
  + Framing C (alias-aware entity), with Tier 1/2/3 renamed to Knowledge Acquisition / Link Recovery
  / Multi-Framing Merge. Zero logic change from s15. Expected: F1 ≈ s15 (validates relabelling).
- **s_linker17b** — unified architecture. Alias discovery runs first (sequential), then all three
  framings (A/B/C) are extracted in parallel (all alias-aware). k=2 voting merge: a candidate
  survives if ≥2 framings agree. Unified evidence-bundle validation. This is the target ICSE story.

## Semver Rationale

Backward-compatible experimental variants. No change to canonical (`s_linker13_min`). No new
external feature. s_linker15 (v2.6.1 production) untouched. Therefore **PATCH → v2.6.2**.

## Source

2026-06-03 session analysis: empirical root-cause investigation of s_linker15b failure
(alias-recovery-only −2.5pp) + s_linker15c (entity hybrid −0.6pp) proving entity pipeline
essential. Design converged on Multi-Framing unification as the ICSE narrative. See:
`.continue-here.md` (session summary).

## Goal

1. Establish whether s_linker17a ≈ s15 (validates renaming is safe, zero logic change).
2. Establish whether s_linker17b matches or exceeds s15 macro F1 (validates unified design).
3. If 17b ≈ 17a in F1: adopt unified architecture as the paper design, retire the two-pipeline framing.
4. If 17b regresses: decide between (a) k threshold tuning, (b) 17a + paper framing, (c) investigation.

**No F1 gate.** Outcome is a design decision, not a numeric threshold.
