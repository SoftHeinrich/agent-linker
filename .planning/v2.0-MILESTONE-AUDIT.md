## 5. Findings & Implications

### What v2.0 proved

1. **The "rule replaced by LLM primitive" thesis has a clean boundary**: rules whose job decomposes into something an LLM can judge from `(component_name, sentence)` alone can be removed (6 of 7 v1.0 rules); rules whose correct answer depends on a project-specific surface convention (dotted-path Java packages, casing conventions) cannot (v1.0 13d/VAR-04 + v2.0 EXT-01 close-empty + Phase 9 TM regression).
2. **Methodology > variant count**: v1.0 retired VAR-04 after one negative. v2.0 spent 6 sub-variants on EXT-01 before reaching the same conclusion. The feasibility-probe gate (introduced mid-Phase 6) cheaply ruled out the entire design space — future rule-removal attempts on this class should probe-first.
3. **Knowledge injection has real but bounded value**: Alias context lifts BBB by +0.7-2.1pp on the LLM judge layer. Not enough to close a structural-rule recall gap, but materially non-zero and worth preserving as a design pattern.
4. **Cross-model gap is a property of the dataset shape, not a defect**: gpt-5.4 holds on 4 of 5 datasets within tolerance; the one regression dataset (TM) is structurally hazardous (component names overlap with generic English, dotted-path identifiers, and platform-name collisions). This is the v2.0 cross-model evidence — published as a finding per the v2.0 thesis.
