# Testing

## Framework

### Pytest Configuration
Project uses **pytest 8.0.0+** as primary test framework.

**Configuration** (from `pyproject.toml`):
```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
python_files = ["test_*.py"]
```

**Test discovery rules**:
- Test files in `tests/` directory named `test_*.py`
- Test functions/classes follow standard pytest conventions
- No custom pytest plugins or markers configured

### Optional Dependencies
Tests require optional `dev` extra:
```bash
pip install -e ".[dev]"
```

Installs: `pytest>=8.0.0`, `pytest-asyncio>=0.23.0`

## Structure

### Tests Directory
Main pytest suite in `tests/`:

| File | Purpose |
|------|---------|
| `test_voting_asymmetry.py` | Unit tests for validation voting modes (union/intersection/adaptive). Zero LLM calls. Tests `_validate_with_evidence()` decision logic across 3 voting strategies. |
| `test_checkpoint_migration.py` | Integration test. Verifies pickle checkpoint loading and migration between linker versions. Uses saved phase data from ablation runs. |
| `test_voting_analysis.py` | Analysis of voting behavior on real checkpoint data. Compares voting modes, analyzes FP/TP impact. |
| `test_mention_type_ablation.py` | Studies impact of mention type stratification (proper-case vs alias vs coref) on link recovery. Loads checkpoint data. |
| `test_12e_variance.py` | Measures run-to-run variance in S-Linker12e across multiple seeds/backends. Documents LLM variance. |

### Root-Level Ablation Scripts
Root directory contains **standalone driver scripts** (not pytest; manual execution):

| File | Purpose |
|------|---------|
| `run_ablation.py` | **Primary ablation runner**. Orchestrates linker variants (ILinker1-3, S-Linker1-12e) against benchmark datasets. Outputs CSV results. Not pytest. |
| `test_prompt_audit.py` | **Prompt audit script** (not a test). Checks prompt constants for data leakage (benchmark term overlap, few-shot coverage, abbreviation teaching). Analyzes whether ambiguity info reduces FPs. |
| `test_judge_multiword.py` | **Heuristic analysis script** (not a test). Examines multi-word name handling in judge phase, boundary condition edge cases. Loads checkpoint data. |
| `archive/test_scripts/` | Historical test/analysis scripts from earlier development phases. Not run in current suite. Examples: `test_variance.py`, `test_judge_ideas.py`, `test_transarc_routing_heuristics.py`. |

**Note**: Root-level test_*.py scripts have misleading names (historical artifact). They are **ablation drivers and analysis tools**, not pytest test suites. Run them manually:
```bash
python test_prompt_audit.py
python test_judge_multiword.py
```

### No Conftest
No `conftest.py` file in project. Pytest fixtures defined inline in test files (rare) or test functions are standalone.

## Mocking

### Mock Strategy
Tests prefer **realistic data over mocks** where possible:

#### unittest.mock Usage
Minimal; used only when linker state needs to be pre-fabricated:

```python
# From test_voting_asymmetry.py
from unittest.mock import patch

linker = SLinker12b.__new__(SLinker12b)  # Create without __init__
linker.doc_knowledge = DocumentKnowledge(aliases=...)
linker.model_knowledge = ModelKnowledge(ambiguous_names=...)
```

#### No LLM Mocking
- Tests explicitly avoid mocking `LLMClient.query()`
- Integration tests load real checkpoint data instead (pre-generated by full runs)
- Unit tests (like `test_voting_asymmetry.py`) operate on linker logic without LLM at all

### Checkpoint-Based Testing
Many tests rely on **pickle checkpoints** saved by full ablation runs:

```python
# Loaded at test runtime
import pickle
with open("results/phase_cache/s_linker10/mediastore.pkl", "rb") as f:
    phase_data = pickle.load(f)
    model_knowledge = phase_data["model_knowledge"]
    doc_knowledge = phase_data["doc_knowledge"]
```

**Rationale**: Captures exact LLM behavior from past runs; enables deterministic unit tests on downstream phases without re-running LLM.

## How to Run

### Full Pytest Suite
```bash
pytest
```

Runs all tests in `tests/` directory. Typical runtime: 30-90s (depending on checkpoint availability).

### Single Test File
```bash
pytest tests/test_voting_asymmetry.py
```

### Single Test Function
```bash
pytest tests/test_voting_asymmetry.py::test_voting_modes_agree_on_unanimous
```

### With Verbose Output
```bash
pytest -v tests/
pytest -vv tests/  # More detail
```

### Show Print Output
```bash
pytest -s
```

### Run Without Checkpoints (Unit Tests Only)
Some tests like `test_voting_asymmetry.py` work offline:
```bash
pytest tests/test_voting_asymmetry.py -v
```

Other tests (like `test_voting_analysis.py`) require checkpoints from `results/phase_cache/`.

### Ablation Runs (Not Pytest)
```bash
# See available linker variants
python run_ablation.py --list-variants

# Run single linker on single dataset
python run_ablation.py --variant s_linker10 --project mediastore

# Run all variants on all datasets (takes hours)
python run_ablation.py
```

Output: CSV files in `results/` with F1, precision, recall per dataset/variant.

### Prompt Audit (Not Pytest)
```bash
python test_prompt_audit.py
```

Generates report on:
- Benchmark term leakage in prompts
- Few-shot example quality
- Abbreviation pattern coverage
- Whether ambiguity classification reduces FPs

## Test Categories

### Pytest Unit Tests (in `tests/`)

#### Voting & Decision Logic (Zero LLM)
- **test_voting_asymmetry.py** — Tests `_validate_with_evidence()` on hand-crafted candidate batches. No LLM calls. Verifies union/intersection/adaptive voting correctness.
- **test_mention_type_ablation.py** — Tests evidence type stratification (proper-case mention vs alias-backed vs coref) on link approval. No LLM calls.

#### Integration Tests (Checkpoint-Based)
- **test_checkpoint_migration.py** — Loads saved checkpoints, verifies format compatibility across linker versions.
- **test_voting_analysis.py** — Analyzes voting behavior on real checkpoint data from full runs. Categorizes FP/TP by voting mode.
- **test_12e_variance.py** — Measures per-run variance in S-Linker12e results. Documents stochasticity and model differences (Claude vs GPT).

### Ablation Drivers (Root Directory, Manual Execution)

#### run_ablation.py
**Purpose**: Evaluate all linker variants (ILinker1-3, S-Linker1-12e) against 5 benchmark projects.

**Execution**:
```bash
python run_ablation.py                      # Run all variants, all datasets (5-10 hours)
python run_ablation.py --list-variants       # Show available variants
python run_ablation.py --variant s_linker10  # Single variant, all datasets
python run_ablation.py --project mediastore  # All variants, single dataset
```

**Output**: `results/ablation_results.csv` with columns:
- variant, project, f1_score, precision, recall, fp_count, fn_count

**Not pytest**: Manual runner script; uses linker classes directly.

#### test_prompt_audit.py
**Purpose**: Detect data leakage in prompts; verify few-shot quality; assess abbreviation teaching.

**Execution**:
```bash
python test_prompt_audit.py
```

**Checks**:
1. **Term overlap**: Are benchmark component names in prompt examples? (should be 0)
2. **Pattern overlap**: Do prompt patterns match real doc sentences?
3. **Abbreviation teaching**: Are benchmark abbreviation styles covered by examples?
4. **Ambiguity utility**: Would passing ambiguity classification to extraction reduce FPs?
5. **Few-shot calibration**: Do judge examples match empirical approval patterns?
6. **Alias coverage**: Do extraction rules document actual alias types?

**Output**: Prints report to stdout; may indicate prompt changes needed.

**Not pytest**: Standalone analysis script.

#### test_judge_multiword.py
**Purpose**: Analyze judge behavior on multi-word component names; test boundary conditions.

**Execution**:
```bash
python test_judge_multiword.py
```

**Analyzes**:
- Judge decision distribution on multi-word vs single-word names
- Impact of CamelCase detection on judge approval
- Intersection voting on borderline candidates
- FP sources (which types of names are over-accepted?)

**Output**: Prints analysis to stdout.

**Not pytest**: Standalone analysis script; loads checkpoint data and replays judge logic.

## Key Test Fixtures & Data

### Checkpoint Format
Pickled dict containing phase outputs:
```python
{
    "model_knowledge": ModelKnowledge(...),
    "doc_knowledge": DocumentKnowledge(...),
    "raw_seed_links": list[SadSamLink],
    "validated": list[CandidateLink],
    "coref_links": list[SadSamLink],
}
```

Location: `results/phase_cache/{linker_variant}/{project}.pkl`

### Benchmark Datasets
5 projects in `/mnt/hostshare/ardoco-home/ardoco/core/tests-base/src/main/resources/benchmark/`:
- mediastore, teastore, teammates, bigbluebutton, jabref

Each contains:
- `text_*/`: documentation text files (one sentence per line)
- `goldstandards/`: ground-truth CSV files with (sentence_number, component_id) pairs
- `model_*/`: architecture model files (.repository)

### Test Data Isolation
- Tests use only data in `tests/` or `results/phase_cache/`
- No direct access to benchmark goldstandards (only through ablation comparisons)
- Checkpoint data is immutable (read-only in tests)

## Running the Full Validation Pipeline

To validate the codebase end-to-end:

```bash
# 1. Run unit tests
pytest -v

# 2. Run ablation on sample (single variant, single dataset — ~2 min)
python run_ablation.py --variant s_linker10 --project mediastore

# 3. Audit prompts for leakage
python test_prompt_audit.py

# 4. Analyze judge behavior (requires checkpoint)
python test_judge_multiword.py
```

Full ablation suite (all 12 variants × 5 datasets) takes 5-10 hours; typically run on CI/CD or overnight.
