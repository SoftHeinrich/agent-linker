# v2.3 β Architecture Spec — Voyager v4 Multi-Role Training

This document specifies the v2.3 mainline architecture, locked via `/gsd:new-milestone v2.3` discussion (2026-06-01). It supersedes the prior `voyager-v4-architecture-proposal.md` — that proposal's R1-R5 conflated linker-internal pipeline stages with training-loop roles; this spec separates them cleanly.

## Thesis

Multi-role training (L + O + D-with-CoT-A + P) produces per-slot rich rules+examples that, composed with axiom skeletons, match or beat hand-authored `prompts_v3.py` on gpt-5.4 macro F1. If validated, the result removes the expert-hand-tuning bottleneck on LLM-pipeline prompt construction.

**Comparison reference:**
- Primary: `s_linker14_voyager` (trained bank + axioms) vs `s_linker13_min` (hand-authored `prompts_v3.py`) — gpt-5.4 macro F1, 5-dataset.
- Secondary: vs `prompts_v3_axiom.py` (axiom-only floor) to attribute lift to trained patterns vs minimal-skeleton baseline.

## Taxonomy Correction

The earlier v4 proposal called its 5 components R1–R5 but conflated two layers:

**Linker-internal pipeline stages** (consume trained prompts; NOT training-loop roles):
- Extraction (LLM call, consumes `ENTITY_EXTRACTION_RULES` slot)
- Alias judge (LLM call, consumes `DOC_KNOWLEDGE_JUDGE_RULES` + `DOC_KNOWLEDGE_JUDGE_EXAMPLES` slots)
- Ambiguity (LLM call, consumes `AMBIGUITY_RULES` + `AMBIGUITY_FEW_SHOT` slots)
- Validation (LLM call, consumes `VALIDATION_RULES` slot)
- Coreference (LLM call, consumes `COREF_RULES` slot)
- Seed disambiguation (LLM call, consumes `SEED_DISAMBIGUATION_RULES` slot)
- Doc-knowledge extraction (LLM call, consumes `DOC_KNOWLEDGE_EXTRACTION_RULES` slot)

**Training-loop roles** (surround the linker during training; defined below):
- L — Linker (runs the pipeline above)
- O — Oracle (error analysis)
- D — Distillator (with CoT-A inline)
- P — Probation gate (mechanical, no LLM)

## Training-Loop Roles

### L — Linker

Runs the s_linker13 pipeline end-to-end with the current bank state injected. Emits final predictions `{(sentence_id, comp_id)}`.

- **LLM cost:** ~7 LLM calls per dataset run (one per pipeline stage), per outer iter
- **Cache:** per-(text_stem, comp_hash, backend, model)
- **Bank injection:** at linker init, load current bank → group patterns by slot → wrap axiom prompts with `LEARNED PATTERNS` header + bullet list of rule_text + example_block content
- **Implementation anchor:** extend or clone `src/llm_sad_sam/linkers/experimental/s_linker13_skill_learned_clean.py`

### O — Oracle (text-aware, role-separated)

Sees gold annotations + L's predictions + sentence text + current bank state. Emits structured failure-mode analysis to drive D.

**Input:**
- Gold annotations for training projects: `set of {sentence_id, comp_id}` pairs
- L's predictions: `set of {sentence_id, comp_id}` pairs
- Sentence text (text-aware mode (i) — locked)
- Current bank state: per-slot pattern list with pattern IDs
- Per-slot linker-internal verdicts: which slot fired what verdict on which candidate

**Output (JSON, fed to D):**

```json
{
  "iter": <int>,
  "split": "<split_name>",
  "L_predictions_summary": {
    "macro_F1": <float>,
    "delta_from_prior_iter": <float|null>,
    "per_dataset": {"<project>": <float>, ...}
  },
  "failure_modes": [
    {
      "id": "FM-<n>",
      "title": "<short title>",
      "affected_slot": "<one of 9 slot names>",
      "symptom": "<what L did wrong, abstract description>",
      "apparent_cause": "<why current bank/axiom rules allow it>",
      "suggested_direction": "<what kind of pattern would address it>",
      "evidence_count": <int>,
      "abstract_example_pair": "<synthesized failure example + correct counter-example, no benchmark surface tokens>"
    }
  ],
  "newly_introduced_errors": [
    {
      "id": "FM-NEW-<n>",
      "introduced_by_bank_pattern": "p_<id>",
      "title": "...",
      "affected_slot": "...",
      "symptom": "...",
      "apparent_cause": "Pattern p_<id> over-triggers / under-triggers in <abstract context>",
      "suggested_direction": "...",
      "evidence_count": <int>
    }
  ]
}
```

**Vocabulary discipline:**
- `title`, `symptom`, `apparent_cause`, `suggested_direction` use instructed abstract vocabulary only
- Allowed: discourse-syntactic-functional terms (subject-position, predicate, anaphora, parenthetical, namespace-prefix, section-heading, sentence-position, qualifier-clause, cross-reference) + structural verbs (over-approved, under-rejected, propagated, missed, expansion, alias-of, container-of, sub-element-of)
- Forbidden: surface tokens from input docs (component names, project terms, technology-specific names)
- `abstract_example_pair` is constructed (synthesized), NOT paraphrased from doc text. Reviewer critic verifies.

**Leak defense:** O's text-aware input does not constitute a leak because O's output never enters the final shipped bank. The leak-relevant boundary is at bank-entry — D's emitted pattern proposals are GATE-06 grep'd + reviewer-critic'd before insertion into the bank. O's intermediate JSON is consumed by D within the same iter then discarded.

### D — Distillator (text-blind, with CoT-A inline)

Sees O's structured JSON output + current bank state. NEVER sees raw text.

**CoT-A inline:** D's prompt requires explicit chain-of-thought abstraction validation BEFORE emitting each pattern. Test pattern mentally against 5 architectural styles (microservice mesh, event-sourced, layered monolith, pipe-and-filter, hexagonal/ports-and-adapters). Only emit if pattern is style-invariant. The abstraction check is part of D's reasoning, not a separate LLM role (R5 is folded into D).

**Output:**

```json
{
  "iter": <int>,
  "patterns_proposed": [
    {
      "slot": "<axiom slot name>",
      "rule_text": "<2-4 sentence rule using discourse-functional vocabulary>",
      "example_block": "TP: <synthesized correct example>\nFP: <synthesized incorrect example>",
      "why_it_transfers": "<reasoning about style-invariance>",
      "abstraction_check_cot": "Tested against microservice/event-sourced/layered/pipe-filter/hexagonal: <verdict + reasoning>. Passes/Fails."
    }
  ],
  "patterns_to_remove": [
    {"pattern_id": "p_<id>", "reason": "<categorical reason>"}
  ]
}
```

**Vocabulary discipline:** Same as O. `rule_text` and `example_block` use discourse-functional vocabulary only. Synthesized examples MUST NOT contain benchmark surface tokens.

**Bank-entry gate (GATE-06 + critic):**
- Every proposed pattern grep'd against `BENCHMARK_TABOO.md` regex
- Reviewer critic LLM call (per pattern) — score for defensibility on a "would this pattern hold for any architectural style?" basis. Used as advisory; D's CoT-A is the primary defense.
- Patterns that fail the grep are NOT inserted. D may be asked to reformulate.

### P — Probation Gate (mechanical, no LLM)

After D's accepted patterns are inserted into the bank (per-batch), P re-runs L with the augmented bank on a probation fold (held-out subset of training projects, or next-iter same training projects). Computes macro F1 delta vs prior-iter L run.

**Rule:** If F1 delta < 0 on probation fold, the WHOLE BATCH of patterns added this iter is rolled back. Per-pattern rollback is NOT used (too fine-grained; reduces signal-to-noise).

**No LLM cost:** uses L's regular LLM calls (which are also cached, so re-runs hit cache). P is decisional logic only.

## Iteration Loop

```
Outer pass N (max 5):
  for project in training_set:
    L_predictions = run_linker(project, current_bank)            # ~7 LLM calls/project (cached)
    O_json = run_oracle(gold[project], L_predictions, text,
                         current_bank, linker_verdicts)           # 1 LLM call/project
    D_proposals = run_distillator(O_json, current_bank)           # 1 LLM call/iter (not per project)
    candidate_patterns = grep_and_critic_filter(D_proposals)      # GATE-06 + critic
    augmented_bank = current_bank + candidate_patterns
    probation_delta = probation_test(augmented_bank, training_set)# uses L (cached)
    if probation_delta >= 0:
      current_bank = augmented_bank
    else:
      log_rollback(candidate_patterns)
  if macro_F1(training_set) >= 0.90:
    break  # converged

After convergence:
  aggregate per-project bank → final_bank.json (union + dedupe across projects)
  evaluate s_linker14_voyager(final_bank) on full 5-dataset, gpt-5.4
  apply 3-tier promotion bar
```

## Bank Persistence

- **Per-project banks during training:** `results/voyager_v4_beta/<split>/<project>_bank.json` updated per outer iter
- **Aggregated final bank:** `results/voyager_v4_beta/<split>/final_bank.json` — union + dedupe (Jaccard ≥ 0.6 floor) + cross-validation (only patterns surviving on ≥2 projects retained)
- **Per-(text, comp, backend, model) cache:** for L's per-stage LLM call outputs + D's reviewer-critic outputs + O's JSON outputs (all on-disk artifacts)
- **Cache root override:** `VOYAGER4B_CACHE_ROOT` env var

## Train/Test Split

**Mainline (Probe + Range tiers):**
- Train projects: mediastore + teastore + teammates
- Held-out test: bigbluebutton + jabref
- Matches Voyager v2 split 1 for direct comparison

**Confirmation tier (only if mainline ≥ 0.87):**
- Run 3-split sweep matching Voyager v2 splits 1+2+3
- Final shipping bank = aggregated across all 3 splits' final banks

## Promotion Bar (Locked)

3-tier on gpt-5.4 macro F1, 5-dataset:

| Tier | Threshold | Action |
|---|---|---|
| STRONG | ≥ 0.9173 (= trim1) | Ship `s_linker14_voyager` with no caveat. Register as `experimental=True`. |
| WEAK | [0.87, 0.9173) | Ship `s_linker14_voyager` with documented caveat. Register as `experimental=True`. |
| FAIL | < 0.87 | Drop v4. Switch v2.3 mainline to Compact-B (R345 single role with structured CoT, per `v2.2-SCOPE-DECISION.md`). |

`s_linker13_min` retains `canonical=True` regardless of v4 outcome. GATE-01 applies only to canonical artifacts; v4 is bound only to 0.87 floor as experimental.

## Locked Constraints

1. **Backend = gpt-5.4 only.** Claude only if super necessary (see `[[feedback-prefer-gpt-backend]]`).
2. **Slot-uniform bank.** All 9 axiom slots receive bank patterns (no mixing static + bank).
3. **Discourse-vocab-only in D's pattern proposals** (Probe A' carry-forward).
4. **GATE-06 grep + reviewer critic at bank-entry boundary.**
5. **Per-(text, comp, backend, model) cache** for all on-disk artifacts.
6. **Static-prompt-elegance** preserved (Voyager-mode runtime injection; no inline prompt-body edits).
7. **R3 vocab anchor:** start from `scripts/voyager_train_tlr_v4_a_prime.py`; do NOT re-derive.
8. **Dual-artifact policy:** s_linker13_min canonical=True retained; s_linker14_voyager ships experimental=True.

## Fallback Contingency: Compact-B

Auto-triggered if v4 macro F1 < 0.87 on mainline split.

**Compact-B definition (from `v2.2-SCOPE-DECISION.md`):** R345 single role with structured CoT. One LLM call internally reconciling: (a) error categorization (O equivalent), (b) pattern distillation (D equivalent), (c) abstraction validation (A equivalent). Cheapest viable architecture.

**Compact-B promotion bar:** same 3-tier as v4 mainline. If Compact-B also FAILs, v2.3 ships a negative finding paper artifact (v4 falsified for SAD-SAM).
