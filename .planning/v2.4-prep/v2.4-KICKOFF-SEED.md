## Design Decisions (LOCKED — do not re-explore)

### Decision 1: Traceability Gate — Gate A (Deterministic FM Citation)

**What**: D prompt must include `addresses_failure_modes` field with a list of FM IDs this proposal addresses. Gate checks: non-empty list AND all cited IDs exist in O's `failure_modes[].id` output for this pass. Reject immediately if list is empty — not advisory.

**Why not advisory**: Advisory mode was effectively what v2.3 had (D had `why_it_transfers` + `abstraction_check_cot` but no FM IDs). Split2 produced 0 commits across 5 passes. The gate must be hard.

**Implementation target**: `scripts/voyager_train_tlr_v4_beta.py` — modify D prompt template and the acceptance check in the training loop.

**Zero LLM cost** — pure JSON field validation.

### Decision 2: Traceability Gate — Gate B (LLM Dual-Direction Judge)

**What**: For each proposal that passes Gate A, run an LLM judge with:
- The proposed pattern (slot, rule_text, abstraction_check_cot)
- The cited failure mode (fm_id, fm_title, fm_symptom, fm_suggested_direction from O's output)
- New errors flagged by O in this slot (from O's newly_introduced_errors[])

**Judge answer format**:
```json
{
  "fixes_cited_fm": true/false,
  "causes_new_error": true/false,
  "confidence": "high" | "medium" | "low",
  "rationale": "<one sentence>"
}
```

**Accept condition**: `fixes_cited_fm: true AND causes_new_error: false AND confidence: high|medium`

**Estimated cost**: ~$0.01/pass (small prompt, short response).

**Implementation target**: `scripts/voyager_train_tlr_v4_beta.py` — new `_gate_b_judge()` function; called after Gate A passes, before probation.

### Decision 3: Drop Probation Re-Run Entirely

Gate A/B replace the probation loop. The probation re-run was the mechanism by which two independent stochastic L runs were compared — Gate B is a semantic check that costs less and is less noisy. Remove `_probation_check()` and all call sites. Keep the L run for metrics only (to compute training macro for convergence condition); do not compare L-before vs L-after.

### Decision 4: Four Supporting Bug Fixes

These must be fixed alongside Gate A/B. They are listed in D-1 todo and confirmed correct:

1. **L cache** — keyed on `(project, bank_content_hash, backend, model)`. Eliminates variance from two independent noisy L runs. L runs with the same bank state should be deterministic.
2. **`prior_f1s` from committed state** — update `prior_f1s` only from the bank state that was formally committed after the last outer pass, NOT from the stochastic `train_f1s_after_l` of the current pass.
3. **Per-project candidate bank** — `candidate_banks` indexed by project, not `candidate_banks[projects[0]]` for all projects. Once banks diverge across projects the single-entry indexing silently uses the wrong bank.
4. **Convergence condition** — replace `len(accepted)==0` (GATE-06 never rejects so this never triggers) with `committed_macro >= CONVERGENCE_THRESHOLD` (actual macro improvement plateau).

### Decision 5: Gap 1 Fix — COREF_RULES Extension (Not DOC_KNOWLEDGE Alias)

**Why DOC_KNOWLEDGE alias approach does NOT work** (do not re-explore):
- Entity extraction (lines 785-803 of `s_linker14_voyager.py`) is batch-mode: 50 sentences processed without window context.
- `local`-scoped aliases are explicitly filtered at lines 788-791 before returning results.
- Even if "server" were extracted as a local alias, there is no sentence window in entity extraction to know it maps to "HTML5 Server" appearing 8 sentences earlier.
- The alias would not be tagged as linked to any specific component — it would be a floating string.

**Why COREF_RULES extension is correct**:
- `_coref_cases_in_context` already has ±5 bidirectional window (lines 969-973).
- SCN resolution ("the server" → "HTML5 Server") naturally fits this window — the antecedent sentence containing the full name is within ±5.
- The gate at line 1017 (`has_standalone_mention(comp, ant_sent.text)`) already handles SCN correctly — antecedent sentence contains the full name, so gate passes.
- The only missing piece is widening the sentence filter at line 962 to include `role_ref_pat` matches (sentences containing "the server" / "the client" etc.) alongside pronoun-containing sentences.

### Decision 6: Gap 1 + 3 Combined — Single COREF_RULES Axiom Update

Gap 1 (SCN: "the server" → "HTML5 Server") and Gap 3 (alias coref: antecedent via known alias) are both anaphoric resolution failures. They are fixed by a single semantic reframing of COREF_RULES:

**Old text (approximate)**: "For each case, decide whether a pronoun in the target sentence grammatically refers back to a component named verbatim earlier in the context. Resolve only when one component is the unambiguous antecedent."

**New text**: "For each case, decide whether a pronoun or role-referential noun phrase in the target sentence refers back to a component named or aliased earlier in the context. Resolve only when one component is the unambiguous antecedent."

Gap 3 specific addition: "When the antecedent sentence contains a known alias of the component (see alias list), set antecedent_via_alias=true." (The code path at line 1017 already checks `antecedent_via_alias` — it was just never exercised because the axiom said "named verbatim".)

### Decision 7: Gap 1 Code Change (~8 Lines in `_coref_cases_in_context`)

The COREF_RULES axiom change has ZERO EFFECT without this code change. SCN sentences ("The server handles X") contain no pronoun, so they fail the existing `PRONOUN_PATTERN` filter at line 962 and never reach the LLM.

**Required change**:
```python
# Build runtime pattern from component terminal words
comp_terminals = {c.name.split()[-1].lower() for c in components if len(c.name.split()) > 1}
role_ref_pat = re.compile(
    r'\bthe (' + '|'.join(re.escape(w) for w in comp_terminals) + r')\b',
    re.IGNORECASE
) if comp_terminals else None

# Expand sentence filter (replaces pronoun_sents)
anaphoric_sents = [
    s for s in sentences
    if self.PRONOUN_PATTERN.search(s.text)
    or (role_ref_pat and role_ref_pat.search(s.text))
]
# replace all uses of pronoun_sents with anaphoric_sents throughout _coref_cases_in_context
```

Additional updates in `_coref_cases_in_context`:
- Update prompt header: "pronoun references" → "anaphoric references (pronouns and role-referential noun phrases)"
- Update JSON template: `"pronoun": "it"` → `"reference": "the server"`
- Variable rename: `pronoun_sents` / `pronoun_count` → `anaphoric_sents` / `anaphoric_count` (lines 719 and 949; code never parses the `pronoun` field from JSON so no parsing changes needed)

The gate at line 1017 (`has_standalone_mention`) is UNCHANGED and CORRECT — SCN antecedent sentences contain the full component name, so the gate passes correctly.

### Decision 8: Gap 2 Fix — SEED_DISAMBIGUATION_RULES Axiom Only

**Empirical safety result (do not re-verify — already confirmed)**:
0/27 MS gold sentences and 0/23 TS gold sentences start with a gerund. Zero risk of killing TPs in training data. Safe to deploy.

**Axiom change**: Add one case to the OTHER category in SEED_DISAMBIGUATION_RULES:
"description of the component's own capabilities without referencing an external participant"

**Why this phrasing is safe**: The safety valve "without referencing an external participant" protects cross-component gerund sentences like "Providing auth to the Storage component" (a legitimate trace link) while rejecting bare responsibility bullets like "Providing a mechanism to store user preferences." (no external participant named).

**No code change required** for Gap 2.
