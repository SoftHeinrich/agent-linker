## Central Thesis

> **For LLM-driven traceability linking, the productive frontier lies in (a) multi-role architecture for skill learning and (b) inference-time iterative refinement of the judge stage. v2.2 ships whichever of these two mechanisms passes the strict GATE-01 promotion bar on a full 5-dataset sweep across both backends — and documents the rest as frontier.**

Combines user-selected pillars from `/gsd-explore` answers:
- Pillar A: Inference-time iterative refinement (Self-Refine, problem-statement preamble, cached rubric)
- Pillar B: Best-in-class judge architecture (Voyager v4 multi-role)
- Pillar C: Upstream-tier rule removal (carry from v2.0 EXT-upstream)

## Sampling Strategy ("be clever")

Per user directive, NOT every variant gets a full 5-dataset × 2-backend sweep. Tiered:

| Sample tier | Datasets | Backends | Purpose |
|---|---|---|---|
| **Probe** | mediastore only | Claude only | Smoke test; cheap kill (~$2) |
| **Range** | mediastore + bigbluebutton | Claude only | Spans easy/hard; mechanism-stability check (~$5) |
| **Cross-model probe** | bigbluebutton only | both Claude + gpt-5.4 | Cross-model behavior on the hardest dataset (~$10) |
| **Confirmation** | full 5 datasets | both backends | ONLY for variants passing Range + cross-model probe (~$30) |

Probe → Range → Cross-model → Confirmation. Probe-fail kills the variant cheaply; only 1-2 variants reach Confirmation.

## Why Voyager v4 First (Phase 14)

The user opened the linker box and noticed s_linker13 internally has proposer + judge — so R1/R2 are partially present. v4 makes the missing role separations explicit:
- R3 (skill distillator) separated from R4 (feedback judge) — currently conflated as "feedback LLM"
- R4 restricted view (no raw doc strings) — closes the surface-rule leak channel
- R5 abstraction validator — closes distributional bias

Phase 14 tests whether this architectural fix solves the Voyager v2/v3 split-fragility. **If it does, v2.2 has a strong training-methodology contribution; if it doesn't, the publishable negative finding refines the limit theorem.**

See `voyager-v4-architecture-proposal.md` for the full 5-role design.

## Phase Skeleton

### Phase 14 — Voyager v4 Multi-Role Architecture
- **14-01** Build 5-role harness (R1 linker, R2 validator, R3 distillator, R4 feedback judge, R5 abstraction validator) — refactor `voyager_train_tlr_v2.py` → `voyager_train_tlr_v4.py`. No LLM cost.
- **14-02** Implement R4 categorical signal + R5 architectural-style transferability test (textbook style library). No LLM cost.
- **14-03** Probe: Split 1 Claude + mediastore. Decision: if +1pp over v2 baseline → continue; else, document and skip remaining v4 work.
- **14-04** If probe passes: full 3-split sweep (matching v2's split design for direct comparison).
- **14-05** Rollup: v4 vs v2 vs v3 + v2.2 verdict (does role separation solve split-fragility?).

### Phase 15 — Problem-Statement Preamble + Cached Rubric
- **15-01** Build canonical TLR problem statement (system prompt, cached). Add to s_linker13_min variant family.
- **15-02** Build per-dataset cached rubric mechanism (generated once per dataset, frozen, reused per sentence).
- **15-03** Probe: Claude + mediastore. Compare F1 vs s_linker13_min baseline.
- **15-04** If probe passes: Range test (MS + BBB). If passes: cross-model probe (BBB Claude + gpt-5.4).
- **15-05** Rollup.

### Phase 16 — Self-Refine on Alias Judge
- **16-01** Wrap alias judge with Reflexion-style 2-iter loop (verdict + structured weakness → revise contested links).
- **16-02** Probe: mediastore Claude. Compare vs s_linker13_min.
- **16-03** Range test if probe passes.
- **16-04** Cross-model probe + confirmation if Range passes.
- **16-05** Rollup.

### Phase 17 — Upstream-Tier Rule Removal
- **17-01** Identify the highest-leverage upstream rule (extraction or coref tier) — analyze BBB FNs from v2.0 EXT-01 evidence.
- **17-02** Build LLM-primitive replacement candidate.
- **17-03** Probe → Range → cross-model → confirmation.
- **17-04** Rollup. If accepted: candidate addition for s_linker14_min.

### Phase 18 — Composition + Promotion
- **18-01** Identify top 1-2 surviving mechanisms across Phases 14-17.
- **18-02** Compose into candidate `s_linker14_min` (composing on top of s_linker13_min).
- **18-03** Full 5-dataset × 2-backend confirmatory sweep.
- **18-04** If passes strict GATE-01 (macro ≥ 0.93 Claude, ≥ 0.8977 gpt-5.4): promote. Update ABLATION-TABLE.md + .tex. Otherwise: ship surviving individual variants as separate v2.2 canonicals, document as negative composition result.
- **18-05** Milestone summary + VERIFICATION.

## Risk Register

| Risk | Mitigation |
|---|---|
| v4 5-role architecture too complex to debug | Phase 14-03 probe gates expansion; if probe fails, document negative result and skip remaining v4 work |
| Sampling strategy misses a mechanism that needs full sweep to show signal | Range tier covers easy + hard; cross-model probe catches asymmetry. If a mechanism passes Range + cross-model probe AND fails Confirmation, that's a publishable finding |
| Self-Refine iteration adds cost without F1 gain | GATE-08 explicit cost-per-improvement audit on every accepted mechanism |
| Upstream rule removal regresses recall on BBB (v2.0 EXT-01 pattern) | Phase 17-03 probe; if BBB recall drops > 6pp on probe, kill the variant immediately |
