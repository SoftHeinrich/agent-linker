## Key Findings

**1. Oracle cache fix confirmed working.** Split-2 committed 12 patterns in Pass 1 (vs v2.4 Phase 23: 0/5 across all passes). Root cause of v2.4 split-2 failure was oracle cache contamination, not the probation gate design. REQ-V25-01 is the decisive fix.

**2. MIN_COMMIT_DELTA=0.005 prevents false subsequent commits.** Passes 2–5 across all 3 splits measured −0.0009 to −0.0277 delta (LLM run-to-run variance). The variance filter correctly blocks O+D from running. This means ≥3/5 passes (REQ-V25-11 SC-2) is structurally impossible under current variance characteristics — not a regression; expected correct behavior.

**3. 15-slot expansion reached.** 5/6 new slots populated in training: `GENERIC_WORD_USAGE_RULES`, `ALIAS_SCOPE_RULES`, `ANTECEDENT_ALIAS_RULES`, `COREF_TERMINAL_SPECIFICITY_RULES`, `DOC_KNOWLEDGE_JUDGE_EXAMPLES`. `SEED_EXTRACTION_RULES` and `SEED_ACTOR_RULES` did not receive patterns (Distillator did not converge toward ILinker3 prompt modifications in the mainline split).

**4. BBB recall ceiling unchanged.** BBB F1 = 73.7% (cross-split), 74.8% (Range). BBB test set not in any training split; Oracle cannot see BBB FNs and cannot learn patterns to address them. This is a structural limitation of the current split arrangement, not a training quality issue.

**5. TM remains highest-error dataset.** TM has 16 FP and 7 FN (cross-split). 6 systematic Oracle failure modes documented in Phase 29 verdict. Container-of mention over-approval (FM-1) and definite-article anaphora attachment (FM-2) dominate.

**6. Cross-split bank is universal by construction.** All 3 splits trained on identical data partitions and produced identical Pass 1 committed banks (L-cache results replicated across splits). Cross-split Jaccard ≥ 0.6 + ≥2-split filter yields 12 patterns — all appearing in all 3 splits. This is strong evidence of robustness, not cross-split diversity.
