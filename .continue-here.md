## Key design decisions made

1. **Entity pipeline stays** — empirically necessary (contributes +2.6pp macro via alias TPs + FP suppression via intersection). Cannot be replaced by alias_recovery alone (s_linker15b proved this).

2. **Two pipelines cannot be cleanly justified as separate concepts for ICSE** — they both solve the same NLP task; the separation is an execution-order artifact (seed runs before alias discovery). Merge is necessary for paper clarity.

3. **Unified Multi-Framing design (s_linker17b)** — alias discovery runs first, then Framings A/B/C in parallel (all alias-aware), k=2 voting merge, unified evidence-bundle validation. This is the clean ICSE story.

4. **s_linker17a** = pragmatic option if 17b regresses — current architecture with ICSE-friendly naming, acknowledging execution constraint in the paper.
